# STS3215 Servo Spec

## Identification

- **Manufacturer:** Feetech (FeiTe)
- **Model:** STS3215
- **Model number register (`0x03`):** 777
- **Firmware:** 3.10 (major `0x00`=3, minor `0x01`=10)
- **Family:** STS/SCS series (serial bus servos, TTL single-wire half-duplex)
- **Protocol:** SCS/TTL — see [protocols/feetech-sts-scs.md](../protocols/feetech-sts-scs.md)

## Electrical (measured on this bench)

| Parameter | Value | Notes |
|-----------|-------|-------|
| Supply voltage | 12.0 V | Measured at the servo via register `0x3E` (120 -> 12.0 V). |
| Idle temperature | 31-33 °C | Register `0x3F`, no load, ambient. |
| Baud rate | 1000000 (1 Mbps) | Only working rate. Silent at 500000, 250000, 115200, 57600. |
| Angle limits | 0 / 4095 | Unrestricted — EEPROM registers `0x09`/`0x0B`. The servo will not protect itself. |
| PID Kp / Kd / Ki | 32 / 32 / 0 | EEPROM `0x15`/`0x16`/`0x17`. Note order: Kd before Ki. |
| Idle current | 300 mA | Bench PSU readout, servo powered, not moving, torque off. |
| Move current | 0.54 A | Bench PSU readout, during a ~10° move. |
| Stall current | ~0.67 A (8 W spike) | Measured via PSU power readout during manual pressure test: pulling the arm's end effector downward spiked draw from ~3.6 W idle to ~8 W. Brief spike under manual pull — a sustained hard jam may read higher if the PSU current limit does not clip it. |

## Physical interface

- **Connector:** 3-pin TTL (V+, GND, Signal)
- **URT-1 port:** SCS/TTL header (3-pin) — **not** the 4-pin SMS/RS485 header
- **Adapter in use:** CH340 USB-serial (URT-1), VID:PID `1A86:7523`
- **Container port:** `/dev/serial/ch340` (stable alias for `ttyUSB0`)

| Pin | Function |
|-----|----------|
| 1 | V+ (servo power, 12 V) |
| 2 | GND |
| 3 | Signal (half-duplex TTL serial) |

The URT-1 handles half-duplex direction switching in hardware, so the software treats it as a normal full-duplex serial port.

## Servo configuration (this bench)

| Parameter | Value |
|-----------|-------|
| Servo ID | 1 (factory default) |
| Baud register `0x06` | `0` (= 1 Mbps) |
| Torque enable `0x28` | 0 at rest; auto-set to 1 by a goal write |
| Position range | 0-4095, centre 2048 |

The servo currently sits near its **upper** limit: resting position ~4016-4072 out of 4095, leaving only ~7° of upward headroom. Move **downward** (toward 2048) for any testing.

## Motion behaviour (measured)

Safe-move recipe: set gentle acceleration (`0x29 := 10`), speed limit (`0x2E := 300`), seed the goal to the present position, verify the goal readback, then write the target.

| Move | Commanded | Achieved | Error |
|------|-----------|----------|-------|
| First small move | 5° (57 counts) | 4.83° (55 counts) | 0.18° |
| 10° move | 9.9° (113 counts) | 9.76° (111 counts) | 0.14° |
| 3× back-and-forth 10° | 9.9° each | 9.84° each (112 counts) | ~0.06° |

- Moves complete in ~0.6 s for a 10° step at speed 300 / accel 10.
- Load register peaks at ~96 (of 1023) during a 10° move, drops to ~24 (holding torque) at rest.
- Status byte remains `0x00` across all moves (no errors).
- Position returns exactly to start after matched back-and-forth moves.
- Behaviour is identical after an unplug + replug (cold start), confirming the safe-move recipe works from RAM defaults.

## Safety notes

1. Move downward only (toward 2048). Upward hits the mechanical limit within ~7°.
2. Small moves only (1-10°). Never command a full-range swing as a first move.
3. Never write `0x28 := 1` directly — see the protocol doc for why.
4. Always set acceleration (`0x29`) to a small non-zero value before moving; `0` means *maximum*.
5. EEPROM writes (ID, baud, factory reset, calibrate, angle limits) are off-limits unless the human explicitly asks.
